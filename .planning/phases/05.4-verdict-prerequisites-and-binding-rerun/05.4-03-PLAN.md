<objective>
Fix two independent, file-disjoint bugs surfaced by Phase 05.3 T6 dry-run:

**Bug C — Look-ahead bias in fill_model fit.** `fill_model.refit_loop.refit_once` always uses `await chain_time.now_cached()` for `window_end_ts`. In live mode that's correct (now ≈ chain_ts). In backtest mode, the engine reads parquet covering ~25 days but the fitter sees `now() ≈ 2026-05-04` — fitting on data 25-30 days AFTER the replay tick. CONTEXT.md cites a 30× p_fill underestimate. Fix: thread `current_chain_ts` through `refit_once` so backtest callers can bound `window_end_ts ≤ current_chain_ts`. Live callers pass `None` (unchanged behavior).

**Bug D — `pnl_pendle` missing from persisted decision_log parquet.** `_flush_decision_log_to_parquet` (replay.py:813-852) writes a list-of-dicts to parquet via `pl.DataFrame(entries)`. The per-tick HOLD/CANCEL row schema (lines 777-792) does NOT include `pnl_pendle`; only the `FILL_REALIZED` row (lines 1471-1483) does. Polars infers a heterogeneous schema and either nulls or drops the column on write. In-memory aggregation works (uses `entry.get("pnl_pendle", 0.0)`) but parquet-side reconstruction is biased.

Both bugs have file-disjoint code paths and can be fixed in parallel inside one plan. Loss-model has the same bug shape as Bug C (same `refit_loop` pattern); CONTEXT.md recommends quantify-and-defer for loss_model, but the implementation work to fix it mirrors the fill_model fix verbatim — so the choice is included as an explicit decision in Task 2.

Output: Two regression tests (one per bug); two-or-three engine source modifications; architecture co-commit; LLM Wiki page each.
</objective>
