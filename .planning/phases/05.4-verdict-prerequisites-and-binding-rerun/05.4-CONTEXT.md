### Why sequential, not wave-parallel

Earlier reasoning treated the 4 bugs as parallel. Self-review (recorded in this session) revised: **Bug B may be a cascade of Bug A**. Specifically, the replay-loop boundary at trade #65 (~2026-04-08, 1 epoch + 17h after start) is suspiciously close to the prior→current epoch transition. If the empty `_calibration_history` produces a NaN/divide-by-zero in some downstream component on a specific tick boundary, fixing Bug A may auto-resolve Bug B. So 05.4-02 starts only AFTER 05.4-01 lands and is allowed to reduce to "no-op, was a cascade — document".

Bug C and Bug D are file-disjoint from A/B (different code paths) and from each other (predict.py + expected_loss.py vs decision_log writer schema), so 05.4-03 can run wave-parallel with 05.4-02.

### 5th bug may exist (explicit caveat)

The Phase 05.3 T6 investigation read: JSONL event-frequency map, baseline decision_log, baseline `results.parquet`, calibration loader code, replay loop entry. It did **not** read: the 6 cancel_latency_sweep rows, 6 competition_sweep rows, 2 forfeit_branch rows (which DID complete cleanly), 26 partial perturbation_grid rows, or any of the 67 sweep-child decision_logs.

A 5th bug could be lurking. **Phase 05.4-04 includes an explicit escape valve**: if the verdict re-run produces `p5` outside `[pass_lo=0.42, pass_hi=18.10]`, route to **Phase 05.5 (sixth-bug investigation)** before lifting the halt. Do not assume the 4 known bugs are exhaustive.

## Classification rule (pinned in band JSON)

The band JSON's `classification_rule` block is the single source of truth for verdict classification. Read it programmatically; do not duplicate the multipliers in plan code:

```json
"classification_rule": {
  "pass_lo": 0.42042,
  "pass_hi": 18.095182,
  "fail_lo": 0.0,
  "pass_lo_multiplier": 0.5,
  "pass_hi_multiplier": 1.5,
  "rationale": "PASS if p5 ∈ [pass_lo, pass_hi] (= [0.5×low, 1.5×high]); FAIL if p5 < fail_lo (negative EV after fills); FLAG otherwise (sixth-bug suspected, route to Phase 05.5 before halt-lift)."
}
```

The 0.5× / 1.5× multipliers represent ~50% operator-review margin around the [low, high] band's 14× spread. The spread reflects unresolved Pendle backend uncertainty (sigma_others definition: raw 165 vs eligible-population 329). If 05.4-03 Bug C is fixed AND look-ahead bias is shown to be material AND the band must be widened, the regenerated band's `classification_rule` will be picked up automatically by 05.4-04.
