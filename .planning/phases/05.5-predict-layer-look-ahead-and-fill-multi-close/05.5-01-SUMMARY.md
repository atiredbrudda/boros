# Phase 05.5 Plan 01: Predict-layer look-ahead — read-path fix Summary

**One-liner:** Added a keyword-only `current_chain_ts` SQL upper bound to `get_latest_fit` and `get_latest_loss_grid` (and the breaker private fallback `_get_any_latest_loss_grid`), plumbed `req.current_chain_ts` through `predict()` and `expected_loss()`, and replaced the silent `*_age_s = 0.0` coerce with `RuntimeError` (Phase-4 contract amendment Option A). Closes the predict-layer look-ahead bug at all 6 enumerated read sites.

## What changed and why

Phase 05.4-03 closed the *write-side* look-ahead bug (`refit_once` now accepts
`current_chain_ts` and bounds `window_end_ts ≤ current_chain_ts`). But the
*read-side* guard in `predict.py:91-106` was a `log.warning` + silent
`fit_age_s = 0.0` coerce. Accumulated cross-run rows in `state.fill_model_fits`
(future-dated artifacts from prior live runs) were still returned by
`get_latest_fit` and silently treated as fresh.

Empirical signal: 266,740 `predict_future_dated_fit` events on a single side in
killed binding run `01KQYNPPE2CB46414WKHEGCZP5`, with zero downstream fill
activity. Same class of bug applies to `loss_model` (with a 90-day vs 14-day
window — smaller relative bias but same shape) and to the breaker private
fallback `_get_any_latest_loss_grid`.

This plan applied a SQL-layer chain-ts upper bound at both retrievals and at the
breaker fallback, plumbed `req.current_chain_ts` from `predict()` and
`expected_loss()`, and converted the silent-coerce branch to `RuntimeError`.

## Phase-4 contract amendment (Option A — RuntimeError)

The post-filter `*_age_s < 0` branch is replaced from:

```python
log.warning("fill_model.predict_future_dated_fit", ...)
fit_age_s = 0.0
```

to:

```python
log.error("fill_model.predict_negative_age_after_filter", ...)
raise RuntimeError(
    f"negative fit_age_s={fit_age_s} after chain-ts filter — "
    f"clock skew or stored artifact corruption ..."
)
```

**Rationale (RESEARCH §Open Question 1):** post-fix, this branch is unreachable
from a correct backtest (the SQL filter excludes future-dated rows). Remaining
triggers are real bugs:

- Live-mode clock rollback (chain_time.now_cached returns smaller timestamp than
  a previously persisted `fit_window_end_ts`).
- Stored-artifact corruption (a row was persisted with a future `fit_window_end_ts`
  by some out-of-band path — the write-path lint should already block this; if it
  fires, the lint missed something).

Both warrant halting the brain. Silent coerce was load-bearing for the bug —
it absorbed the symptom and removed the operator signal. Phase-4 contract
amendment formalizes the new behavior.
