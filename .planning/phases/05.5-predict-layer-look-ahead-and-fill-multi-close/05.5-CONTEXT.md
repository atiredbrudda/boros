## Why this phase exists

Phase 05.4-03 commit `d954bc5` was titled *"Bug C — bound `fill_model.refit_once` window_end_ts by current_chain_ts"*. The fix bounded the **write** path of the fill_model fit loop. The **read** path (`get_latest_fit` in `fill_model_fits.py:86-98`, `get_latest_loss_grid` in `loss_grid_artifacts.py:73-84`) has no `current_chain_ts` filter and uses `ORDER BY *_window_end_ts DESC LIMIT 1`. SQLite tables persist artifacts across runs, so a backtest replaying historical chain time picks up future-dated rows from prior runs / live-mode fits. The predict path (`predict.py:92-106`, `expected_loss.py:101-111`) catches the resulting negative `*_age_s`, logs a `*_future_dated_*` warning, then **silently sets `*_age_s = 0.0`** and uses the future-fitted parameters as if they were fresh.

Empirical evidence from run `01KQYNPPE2CB46414WKHEGCZP5` (killed 2026-05-06 21:22Z):

| event | count |
|---|---|
| `loss_model.future_dated_grid` | 266,740 |
| `fill_model.predict_future_dated_fit` | 266,740 |
| `loss_model.sparse_cell_fallback` | 266,740 |
| any fill / close / pnl_realized | **0** |
| `backtest.replay.seeded_initial_order` | 4 (seed works correctly) |
| `backtest.row_written` | 1 (baseline only) |

The seed places correctly. The fits run (16,590 `fit_completed` events on degraded-but-windowed data). But every `predict()` and every `expected_loss()` call reads a future-dated artifact and treats it as fresh, so the strategy effectively runs on the wrong model coefficients for every tick of the 26-day historical replay.

Loss model is worse: only ONE artifact exists on disk (`window_end_ts=1777799610` = 2026-05-03 18:13:30 UTC). The backtest replays chain timestamps from 2026-03-27 to 2026-04-22 — every single call hits the future-dated branch. That matches the observed 266,740 events on a single side.

## Bugs in scope

### Bug 1 — Predict-layer look-ahead (load-bearing)

**Read sites with no `current_chain_ts` filter:**
- `python/src/boros_brain/state/writers/fill_model_fits.py:86-98` — `get_latest_fit(sqlite_path, market_id, side)`
- `python/src/boros_brain/state/writers/loss_grid_artifacts.py:73-84` — `get_latest_loss_grid(sqlite_path, market_id, side)`

**Predict sites with silent fresh-coercion of future-dated artifacts:**
- `python/src/boros_brain/fill_model/predict.py:80-106` — `fit_age_s < 0` → log + `fit_age_s = 0.0`
- `python/src/boros_brain/loss_model/expected_loss.py:90-111` — `grid_age_s < 0` → log + `grid_age_s = 0.0`

**Required fix shape:**
1. Add `current_chain_ts: int | None = None` to both retrieval functions; when set, append `AND *_window_end_ts <= ?` to the SQL.
2. Pass `req.current_chain_ts` through `predict()` and `expected_loss()` at the read sites.
3. Decide and document the Phase-4 contract amendment: with the chain-ts filter in place, the negative-age branch is unreachable from a correct backtest. Two options — (a) keep the branch as a defensive log + raise (asserts a real clock-rollback) or (b) remove it entirely and let `fit is None` handle it. Both `predict.py:1-11` and `expected_loss.py:1-15` say *"Design-locked. Any change to this signature is a Phase-4 breaking change."* — so this contract amendment must land with a wiki supersedence.
4. Live-brain regression: when `current_chain_ts=None`, behavior is byte-identical to today.

### Bug 2 — Fill multi-close (co-scoped, smaller)

**Site:** `python/src/boros_brain/backtest/replay.py._handle_trade_event` (and adjacent block-iteration logic).

**Mechanism:** After `queue_ahead_yu` is zeroed on first fill detection, every subsequent trade event in the same Arbitrum block satisfies `0 <= evt_size_yu`, scheduling a redundant `ScheduledClose` for the same order. Observed in PID 18460 (`01KQTMW2VE7HF408T4V6XV5TDW`) on April 8 2026 at `ts=1775637304`: 11 closes scheduled for one fill on `initial_01KQTMW2VE7HF408T4V6XV5TDW_long`. Reported fill loss −1.73 PENDLE; true cost ≈ −0.16 PENDLE (~11× inflation).

**Required fix shape:** track `_pending_close_order_ids: set[str]` per tick; in `_handle_trade_event`, after scheduling the first close for an order, skip that order for the remainder of the block's events; clear the set at the tick boundary.

This is co-scoped because Bug 1's fix lets fills actually realize in the simulation; without Bug 2, those realized fills will be cost-inflated 11× and bias the verdict toward FAIL.
