## Task 1: _iter_chain_seconds + tick_period_s knob (COMPLETE)

### _iter_chain_seconds generator (replay.py)

Algorithm: peekable iterator over `real_events`. Yields `(chain_ts, evt)` for real events at their `blockTimestamp`, and `(t, None)` for every synthesised second between consecutive real events (step = `tick_period_s`). Stops at `last_real_event_ts` (no look-ahead, INFRA-14).

Edge cases handled:
- Same-block burst (dt=0): both real events yielded in eventIndex order; no synthesised tick between them
- Empty input: zero tuples (no exception)
- Single event: exactly one tuple
- `tick_period_s=10.0`: yields one tuple per 10 seconds

### tick_period_s knob (config.py + schema.py)

`BacktestConfig.tick_period_s: float = Field(1.0, ge=0.1, le=60.0)` added. Propagates to manifest leaf set (PROTO-04). Manifest leaf count tests incremented by 1.

## Task 2: Main event loop wiring + decision_log streaming + fill detection (COMPLETE)

### Main event loop replacement (replay.py)

Replaced the raw `for evt in itertools.chain([first_evt], events_iter)` loop with:
```python
for chain_ts, evt in self._iter_chain_seconds(chained_iter):
    if evt is not None:
        self._maybe_anchor_snapshot(chain_ts, evt)
    await self._maybe_emit_tick(chain_ts, calib)
    if evt is not None:
        self._detect_inter_event_fills(evt, chain_ts)
        self._handle_trade_event(evt, chain_ts)
    self._fire_scheduled_closes(chain_ts)
self._flush_decision_log_to_parquet(final=True)
```

`_maybe_emit_tick` now fires every second — reward accrual is no longer gated on real trade events.

### decision_log streaming sink

`_flush_decision_log_to_parquet(final: bool)`: writes entries to `{output_parquet_root}/run_id=<ULID>/decision_log/part_NNNN.parquet` using polars. Non-final flush clears in-memory list; final flush leaves tail intact for test consumers. `_decision_log_stream_threshold = 100_000` entries (public attribute for test lowering). Exception is non-fatal: logs warning, keeps entries in memory.

### Inter-event fill detection (E4 verdict: sim_bug_under_counting)

`_detect_inter_event_fills(evt, chain_ts)`: checks whether `evt.rate` crosses our edge (long: rate ≤ clo_lower; short: rate ≥ clo_upper) for each in-flight order with `queue_ahead_wei == 0`. Schedules a close via `latency_scheduler` when crossing detected. Conservative approximation using current event rate as proxy.

E4 outcome: n_crossings_lo=6, n_crossings_hi=9 over 237 events in the 26-day window. The sim previously reported n_fills=0 across this window — confirmed under-counting.
