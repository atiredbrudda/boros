<objective>
Wave 4: Bug #4 fix. Currently `_maybe_emit_tick` only fires on real trade events (~9/day on the binding market). Real bot runs at 1 Hz continuously. Synthesise reward-accrual ticks at 1 Hz on the chain-time clock between consecutive trade events. Reward accrual should happen on every second, not just on trade arrivals.

Adds an `_iter_chain_seconds` helper that yields `(chain_ts, evt_or_None)` for every second in `[first_ts, last_ts]` — real events interleaved at their chain_ts; intermediate seconds yield `evt=None` (synthesised reward-accrual ticks). The main `run()` loop iterates over this and dispatches per type.

Performance discipline: 1 Hz × 26d = 2.25M ticks per market. Decision-log entries stream to Hive-partitioned parquet at 100k boundaries to bound peak memory; sigma_others cache from W3 already in place; AMM cache already in place; per-tick work is dict lookup + one evaluate_decision call + one append.

Wave 0 E4 outcome integrates here: if the n_fills audit verdict is `sim_bug_under_counting`, this plan also adds inter-event fill detection. If `real_no_fills`, this plan stays purely on reward-tick synthesis.

Purpose: Without 1 Hz tick synthesis, reward accrual is suppressed by ~10,000× (only credited at trade events). This is the second-largest engine bug.

Output: 1 Hz reward-accrual ticks; full-epoch integration test passes to 0.01% relative tolerance; wall-time bench under 10 min; decision_log streamed; no look-ahead.
</objective>

    ```
    def _iter_chain_seconds(
        self,
        real_events: Iterator[dict[str, Any]],
    ) -> Iterator[tuple[int, dict[str, Any] | None]]:
    ```

    Algorithm (concrete steps):

    1. Get `tick_period_s = int(self.config.backtest.tick_period_s)` (cast to int; sub-second periods truncate to 1).

    2. Implement as a generator. Use a peekable iterator pattern: collect the first event into `first_evt = next(real_events, None)`. If None, return immediately (empty generator).

    3. Yield `(int(first_evt['blockTimestamp']), first_evt)`. Set `prev_ts = int(first_evt['blockTimestamp'])`.

    4. For each subsequent `evt` in real_events: let `next_ts = int(evt['blockTimestamp'])`. If `next_ts > prev_ts + tick_period_s`: yield `(t, None)` for `t in range(prev_ts + tick_period_s, next_ts, tick_period_s)`. Then yield `(next_ts, evt)` (regardless of whether next_ts equals prev_ts — handles same-block burst). Set `prev_ts = next_ts`.

    5. After all real events consumed: do NOT extrapolate beyond last_ts (no look-ahead). The iterator stops at `last_ts`.

    Edge cases:
    - Two events at same `blockTimestamp` (different `eventIndex`): yield both real events in iteration order, no synthesised tick between them.
    - First and last events are real events; synthesised ticks only between them.
    - `tick_period_s = 1`: yields one tuple per second (default 1 Hz).
    - `tick_period_s = 10`: yields one tuple per 10 seconds.
