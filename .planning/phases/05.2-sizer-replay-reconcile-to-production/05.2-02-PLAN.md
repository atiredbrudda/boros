<objective>
Bug #1 fix. Rename `notional_per_yu_usd` → `margin_per_yu_usd` across the sizer config, optimizer, every callsite, both strategy YAMLs, and the architecture diagram. The semantic was wrong (placeholder hardcoded to BTC notional), but the algebra is unchanged. Per the 2026-04-30 dapp probe (CONTEXT.md), `margin_per_yu_usd ≈ $18.30` for the binding market, which makes `q_max = 100 × 0.9 / 18.30 ≈ 4.92 PENDLE-YU` (not the prior collateral-constrained `q_max = q_min ≈ 0.001`).

Adds Optional per-market `margin_per_yu_usd` + `daily_volatility_pct` + `liquidation_buffer_safety_n` fields to `MarketCalibration` so per-market overrides are introspectable while v0.5 single-market default lives on `BotConfig.sizer`.

Purpose: Without this rename, the sizer suppresses APR by ~5,000× (the dominant bug). After this rename, q_max reflects real margin economics.

Output: `BotConfig.sizer.margin_per_yu_usd` knob; Pydantic schema with `extra='forbid'` rejects the old name; YAML and architecture diagram synchronized; manifest reflects rename.
</objective>
