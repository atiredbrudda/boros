```python
# Bug #3 fix: read sigma_others from parquet at each tick, not from
# (perpetually empty) competition_history. Mirror live CompetitionTracker.
def _read_sigma_others_from_parquet_at_ts(
    self,
    chain_ts: int,
    q_me_pendle: float,
) -> float:
    """Returns Σ_others = sum(raw_book_in_range at latest snapshot ≤ chain_ts) − q_me.

    Raises EmptyCompetitionPoolError if no parquet rows found for this market
    at this chain_ts. The floor `sigma_others_min_pendle` is applied AFTER the
    empty-pool guard — an empty read is real engine failure, not numerical noise.
    """
    market = next(
        (m for m in self.config.markets if m.market_id.endswith(self.market_id)),
        None,
    )
    if market is None:
        raise EmptyCompetitionPoolError(
            f"No MarketCalibration entry for {self.market_id} in BotConfig.markets"
        )
    clo_lower = float(market.clo_lower_thresh)
    clo_upper = float(market.clo_upper_thresh)

    # Lazy-cache the order_book_raw parquet (same pattern as _amm_raw_df).
    if self._order_book_raw_df is None:
        raw_dir = self.parquet_root / "order_book_raw"
        # Reuse the prefix-matching helper from _check_amm_conservation
        files = self._market_specific_parquet_files(raw_dir)
        if not files:
            raise EmptyCompetitionPoolError(
                f"No order_book_raw parquet for market_id ending {self.market_id}"
            )
        df = pl.read_parquet(files)
        # Normalise sz_float / sz column name + snapshot_ts cast to Int64.
        if "sz_float" in df.columns and "size" not in df.columns:
            df = df.rename({"sz_float": "size"})
        if df["snapshot_ts"].dtype == pl.String:
            df = df.with_columns(pl.col("snapshot_ts").cast(pl.Int64))
        self._order_book_raw_df = df

    df = self._order_book_raw_df
    # Latest snapshot ≤ chain_ts
    snap_df = df.filter(pl.col("snapshot_ts") <= chain_ts)
    if snap_df.is_empty():
        raise EmptyCompetitionPoolError(
            f"No order_book_raw snapshot at or before chain_ts={chain_ts} for {self.market_id}"
        )
    latest_ts = snap_df.select(pl.max("snapshot_ts")).item()
    in_range = snap_df.filter(
        (pl.col("snapshot_ts") == latest_ts)
        & (pl.col("tick") >= clo_lower)
        & (pl.col("tick") <= clo_upper)
    )
    total_raw = float(in_range.select(pl.sum("size")).item() or 0.0)
    sigma_others = max(0.0, total_raw - q_me_pendle) * self.sigma_others_multiplier
    # Floor applied AFTER the read succeeded — guards against numerical zero, not data absence.
    return max(sigma_others, self.config.reward_share_model.sigma_others_min_pendle)
```

## Bug #6 Hypotheses Ranked by Likelihood

If Wave 5's re-run lands materially below ~415% USD-APR (e.g. < 100% USD-APR), one of the following bugs must exist. They are ranked by likelihood given the dapp-probe evidence.

### Hypothesis A — Effective-pool weighting (HIGHEST likelihood, ~60%)

**Claim:** Pendle's reward formula doesn't sum the cumulative-in-range orderbook directly. Operator empirical back-calc shows long pool ≈ 75 YU vs orderbook cumulative `[9300, 9500]` sum of 0.66 (just 0.8%, 0.9% ticks) or 165.74 (incl 0.7%) — neither matches.

**Suspected formula candidates:**
1. **Proximity weighting**: orders nearer the mid-rate get a larger reward weight. If mid-rate is in `[9300, 9500]`, deepest orders contribute less.
2. **Time-active weighting**: orders that have been resting longer get amortised reward credit (`t_frac` in our reward-share model is per-Q_me; this would extend to Σ_others as well).
3. **Tick-size-bucketed weighting**: combined book at coarser tick aggregations contributes differently than raw.

**Falsifying test (W3 acceptance row, marked `xfail strict=False`):**

```python
# test_sigma_others_in_dapp_probe_range
def test_sigma_others_matches_dapp_probe_pool_size():
    """Empirical long pool from dapp probe ≈ 75 YU. If the parquet sum at
    the binding market's [9300, 9500] is materially different, weighting
    is the next investigation."""
    sigma = engine._read_sigma_others_from_parquet_at_ts(
        chain_ts=1700000000,  # mid-window
        q_me_pendle=0.0,
    )
    assert sigma == pytest.approx(75.0, rel=2.0), (
        f"sigma_others={sigma} differs > 2× from dapp-probe pool size 75 YU; "
        f"investigate effective-pool weighting (Bug #6 hypothesis A)"
    )
```

**Resolution path:** E5 (operator, low-priority) — find Pendle's published LO Liquidity Reward formula in their docs. If documented, extract verbatim and replace the parquet-sum proxy.

### Hypothesis B — Sparse-tick fill detection (~25% likelihood)

**Claim:** Even with W4's 1 Hz reward-accrual synthesis, fill detection still depends on **real** trade events. If a real trade crosses our edge between events, but our hourly snapshots don't catch it, fills are still under-counted. The current `_handle_trade_event:_trade_consumes_order` uses `evt_size >= queue_ahead_wei` as a proxy — this assumes the order's queue position only updates on observed events.

**Falsifying test:**

```python
    )
```

### Hypothesis C — loss_grid fallback degradation (~10% likelihood)

**Claim:** `loss_model/replay.py:_REPLAY_SQL` uses Phase-1 column names (`marketId`/`size`) vs Wave-1 parquet schema (`market_id`/`size_float`). Result: `fit_status=degraded`, `coarse_bound=0.02 PENDLE`. Was partially fixed in `7244986` (the rerun stale-inputs commit) but only for the binding market; other shortlist markets may still degrade.

**Why low likelihood:** This affects `E[loss|fill]` not reward accrual. Bug #4's reward suppression (10,000×) dwarfs any loss-model error. Even if `E[loss]` were off by 100×, the reward term dominates the EV equation by orders of magnitude.

### Hypothesis D — `t_frac` always 1.0 (~3% likelihood)

**Claim:** `synthetic_orders` always set `t_frac=1.0` (replay.py:262, 360). In a real epoch, `t_frac` should be the fraction of the epoch the order has been active. With 1 Hz ticks, `t_frac` should advance from `0` to `1` over the epoch. If the order is placed mid-epoch, the reward should be discounted by `(epoch_end - placed_at) / epoch_duration`. This may already cancel out at steady state, but matters at edges.

**Why low likelihood:** Steady-state runs (mid-epoch) are dominant; edge effects don't change the order-of-magnitude verdict.

### Hypothesis E — `current_features` zeroed out (~2% likelihood)

**Claim:** `replay._build_evaluate_input` populates `current_features = {name: 0.0 for name in whitelist}` (replay.py:580–583). The fill-model expects real basis_spread / imbalance / sin_settlement / cos_settlement / ewma_vol values. With all zeros, `p_fill` is at the model's intercept-only prediction — could be wildly different from reality.

**Why low likelihood:** The bug is on the loss / fill side, but verdict is dominated by reward accrual. P(fill) error doesn't change reward time-weighted accrual, only the fill-loss subtraction. Bug #4's fix should reveal whether this matters.
