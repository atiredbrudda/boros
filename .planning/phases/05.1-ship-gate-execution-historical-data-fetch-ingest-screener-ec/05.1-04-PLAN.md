<objective>
Wave 3 - operator-driven calibration on the Wave-2 shortlist. For each market in `var/reports/shortlist.json`: (1) operator-calibrate the reward budget via `python -m boros_brain.reward_model calibrate <market>` writing a `state.market_reward_calibration` row with `data_source='operator'` per Phase 3 LOCKED D-01, and (2) fit the Phase-2 fill model for both sides via `python -m boros_brain.fill_model fit --market <m> --side <s>` so Wave 4's backtest has real per-(market, side) artifacts. Wiki-file both calibrations + the fill-fit goodness-of-fit summary so future sessions can audit the inputs.

Purpose: Wave 4's backtest is the binding ship-gate verdict. It reads `state.market_reward_calibration` for the per-market reward budget (the load-bearing economics input) and `data/parquet/fill_model_artifacts/market_id=<m>/side=<s>/...` for the per-(market, side) fill curve. Without Wave 3, the backtest either crashes (no row) or falls back to last-row-wins last-known calibration - which on a fresh shortlist is the previous market's value, silently corrupting the verdict (RESEARCH.md §Open Questions Q7 lock).

Output: per-shortlist-market calibration rows in SQLite + per-(market, side) fill-fit parquets on disk + 2 wiki pages auditing the operator inputs and fit quality + a temp shortlist YAML wiring the markets into downstream CLIs. Wave 4 unblocks atomically.
</objective>
