<objective>
Phase 05.2 Bug #6 fix (commit `cad821f`) corrected the reward leg of the EV equation. The fill leg is structurally broken in three ways and produces `n_fills = 0` regardless of whether real-market activity reached the strategy's resting tick. The W0 audit's `sim_bug_under_counting` verdict (file: `var/reports/n_fills_audit_verdict.json`) was filed on 2026-04-30 and never closed; this plan closes it.

Three coupled defects:

1. **Units mismatch on queue position.** `queue_ahead_wei = 10**18` is set as "1 ETH-scale" in `_seed_initial_synthetic_order`, but the trade-event comparison `order.queue_ahead_wei <= evt.size_wei` only works when source data emits size as a wei-string. The binding-market parquet has all 235 rows on the float-source path, where the ingester correctly records `size_wei = NULL` per its spec. `evt.get("size_wei") or 0` then coerces null to 0, and the trade handler is dead.

2. **CLO threshold treated as a tick.** `clo_lower_thresh = 9300.0` is in fIndex display units (per `screener/filter.py:97-114`), not order-book ticks. `replay.py` uses it both as the seeded order's `tick` field and — via a `/10_000` rescale — as a rate-fraction in the edge-crossing check. Neither is unit-coherent. The seeded order rests at coordinate 9300, not at the actual outer-edge tick; the rate comparison resolves to "every event crosses the long lower edge" because `0.014 ≤ 0.93` always holds.

3. **Catch-22 on `queue_ahead_wei == 0`.** The W4 inter-event rate-crossing check is gated on `queue_ahead_wei == 0`. The only writer of that value is `_handle_trade_event`, which is dead by (1). Even when the rate-crossing check is unit-coherent, no fill can register.

Without the fix, the ship-gate verdict measures only the gross reward leg of EV (`R_share × P(no_fill)`), with the loss leg (`E[loss|fill] × P(fill)`) silently zero. For a strategy whose thesis is "fills are bad and we avoid them by outer-edge placement", a simulator that cannot detect fills cannot test the thesis. Phase 6 (live hands) would surface the gap immediately on the first real fill.

Output: a unit-coherent fill-detection path; a RED-first smoke test that fails before this plan and passes after; a closed W0 audit verdict; a re-run binding ship-gate whose `n_fills` is consistent with the trade-data crossings.

## Decisions (settled before any code change)

### D1 — Unit convention: YU throughout the fill path

Queue position, trade size, and order size all expressed in YU (`size_float`, the human-scale Pendle YU unit). Drop `queue_ahead_wei` as a field name; rename to `queue_ahead_yu`. `_handle_trade_event` and `_trade_consumes_order` compare `evt.size_float` to `order.queue_ahead_yu`. When `size_float` is null (shouldn't happen post-W1 ingester but defensive) raise — no silent zero.

**Rationale:** the binding dataset emits decimal-float sizes; `size_wei` is null for the entire run. Picking YU lets us use the populated column directly. Wei-equivalent at any size is a function of `margin_per_yu_eth`, not a constant; trying to keep wei semantics requires per-tick conversion that buys nothing.

**Implication for `queue_tracker.py` (live path):** verify (or rename to align) before merging. If the live tracker is wei-native, add a thin adapter at the seam, but do not duplicate semantics across both paths.

### D2 — CLO threshold conversion via the existing screener helper

Seeded order's tick: `tick = _clo_findex_to_tick(clo_lower_thresh, f_index_raw, ttm_days)` for long, upper variant for short. Rate-crossing check: convert `tick` back to a rate-fraction via the inverse of the screener's transform, OR compare against a precomputed `clo_lower_rate_fraction` cached on the engine. Pick whichever does not duplicate the screener's math.

**Rationale:** the screener already owns this conversion. Having two implementations is the bug.

**Implication for SCALE / S calibration:** screener falls back to `_CLO_SCALE_DEFAULT = 5.591e12` and `_CLO_S_DEFAULT = 402_648.0` when `f_index_raw` is unavailable. Replay must use the same defaults via the shared helper, not its own constants.

### D3 — Decouple fill detection from queue gate

`_handle_inter_event_fills`: rate-crossing fires unconditionally (subject to `evt_rate ≤ clo_lower` for long / `≥ clo_upper` for short). Queue position influences expected fill probability via the fill-model `p_fill` term that's already wired into the decision engine, NOT as a hard gate at the simulator level.

**Rationale:** the catch-22 disappears, and the simulator's job is restored to "detect when reality crosses the order's price level". Fill probability under uncertainty is a decision-engine concern, not a simulator concern.

**Implication for double-counting:** keep the existing `_trade_consumes_order` skip-condition (line 896) so that a single trade event can't produce a fill via both paths. Document this with a code comment.
